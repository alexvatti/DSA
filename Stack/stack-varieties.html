🥞 Normal Stack LIFO — Last In, First Out

You may only touch the top. That is why every core operation is constant time.

OperationWhat it doesTime
push(x)Put x on topO(1)
pop()Remove and return the topO(1)
peek() / top()Read the top without removingO(1)
is_empty() / size()Check emptiness / countO(1)
search for a valueMust dig through items below the topO(n)
SpaceOne slot per elementO(n)
With a Python list, append is amortized O(1): occasionally the list resizes (O(n)), but averaged over many pushes it is constant.
Python
stack = []
stack.append(4)     # push   O(1)
stack.append(7)
top = stack[-1]     # peek   O(1)
stack.pop()         # pop    O(1)
not stack           # is_empty O(1)

⬇️ Min Stack LeetCode 155

Store (value, min so far) in every entry. The minimum is always sitting in the top pair, so it is never recomputed.

OperationMin StackPlain stack (scan for min)
push(x)O(1)O(1)
pop()O(1)O(1)
top()O(1)O(1)
get_min()O(1)O(n)
Extra spaceO(n)O(1)
Trade-off: you pay O(n) extra memory to make get_min O(1). A second stack that only holds mins works the same way.
Python
class MinStack:
    def __init__(self):
        self.stack = []                      # (value, min so far)

    def push(self, val):
        m = min(val, self.stack[-1][1]) if self.stack else val
        self.stack.append((val, m))          # O(1)

    def pop(self):      self.stack.pop()     # O(1)
    def top(self):      return self.stack[-1][0]
    def get_min(self):  return self.stack[-1][1]   # O(1)

⬆️ Max Stack LeetCode 716

Mirror image of Min Stack: store (value, max so far). peek_max reads the top pair.

OperationTimeNote
push(x)O(1)Store max(x, previous max)
pop(), top()O(1)Same as a plain stack
peek_max()O(1)Read the max in the top pair
pop_max()O(n)Must find and remove the max from the middle: pop until you reach it, then push the rest back using a helper stack. Needs an ordered structure to go faster (about O(log n)).
Extra spaceO(n)One extra number per entry
push / pop / top / peek_max are O(1) with the pair trick. Removing the max from the middle (pop_max) is what makes the full "Max Stack" problem harder.
Python
class MaxStack:
    def __init__(self):
        self.stack = []                      # (value, max so far)

    def push(self, val):
        m = max(val, self.stack[-1][1]) if self.stack else val
        self.stack.append((val, m))          # O(1)

    def pop(self):       return self.stack.pop()[0]
    def top(self):       return self.stack[-1][0]
    def peek_max(self):  return self.stack[-1][1]   # O(1)

📉 Monotonic Stack kept sorted — four varieties

Keep the stack sorted. A new element pops everything it beats, and each popped element is resolved at that moment. Every element is pushed once and popped once.

Python template (next greater)
stack, ans = [], [-1] * len(a)       # stack holds indices
for i, x in enumerate(a):
    while stack and a[stack[-1]] < x:   # change the test for other varieties
        ans[stack.pop()] = x            # popped item is resolved by x
    stack.append(i)
